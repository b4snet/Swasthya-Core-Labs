# ADR-0001: Technology Stack (.NET 10 LTS / ASP.NET Core)

- **Status:** Accepted
- **Date:** 2026-09-16
- **Owner:** Architecture

## Context

Swasthya Core Labs must be an enterprise-grade LIS/DIS: API-first,
interoperability-first (HL7 v2, FHIR, DICOM), security/audit-first, and
long-lived (multi-year support horizon). The available runtimes on the
development machine at Phase 0 were Node and Python; .NET and Java were not
installed. A foundational, reversible-early decision was required.

## Decision

Adopt **.NET 10 (Long Term Support)** / **ASP.NET Core** / **C#** as the
primary stack, targeting `net10.0`.

- SDK pinned via `global.json` (`10.0.401`, `rollForward: latestPatch`) for
  reproducibility.
- Solution format: `.slnx` (default in .NET 10 SDK).
- Central Package Management (`Directory.Packages.props`) with pinned
  versions and NuGet Audit enabled.
- `.editorconfig` + `dotnet format` for formatting; .NET analyzers enabled;
  warnings as errors; nullable + implicit usings.
- xUnit + `Microsoft.AspNetCore.Mvc.Testing` for tests.
- CI: GitHub Actions (Linux + Windows).

## Consequences

- **Positive:** LTS support horizon; strong static typing; enterprise-grade
  tooling; first-party OpenAPI, health checks, configuration, DI, and
  observability; mature health-interoperability library ecosystem
  (HL7/FHIR) for later phases.
- **Negative:** .NET SDK had to be installed (not preexisting); C# skill
  dependency; ecosystem narrower than JVM/Node for some niche libraries.
- **Alternative considered:** Python/FastAPI (available immediately), Node/
  TS, Java/Spring Boot — rejected for weaker enterprise interop-conformance
  tooling or additional toolchain installation without commensurate benefit.

## Notes

- .NET 8 LTS was considered; **.NET 10 LTS was explicitly chosen as the
  baseline** (per roadmap decision) — no legacy target retained.
- Reversible during Phase 0/1 at minimal cost (only scaffolding exists).
