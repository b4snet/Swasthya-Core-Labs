# ADR-0003: Modular Architecture and Core/Integration Boundaries

- **Status:** Accepted
- **Date:** 2026-09-16
- **Owner:** Architecture

## Context

Swasthya Core Labs must be standalone yet integration-ready for arbitrary
external systems. Premature microservices or over-modeling would add cost;
but unstructured monolith would risk boundary erosion.

## Decision

- **Modular monolith** with enforced layering:
  `Api → Application → Domain`, `Infrastructure` implements ports;
  Domain depends on nothing external.
- **Clear core vs. integration classification** for every bounded domain
  (see `docs/architecture/domain-boundaries.md`).
- Extract-to-services is the documented evolution path only when scaling
  demands it; no early service tax.
- Phase 0 physically scaffolds the project boundaries (empty projects) with
  no implementation.

## Consequences

- **Positive:** single deployable in Phase 1+, controlled boundaries, easier
  to validate and secure; deferral of distributed-systems cost.
- **Negative:** modular monolith must be disciplined to avoid coupling;
  future extraction requires refactoring effort.
- Enforce dependency direction via review now; consider architectural tests
  in later phases.
