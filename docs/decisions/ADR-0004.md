# ADR-0004: Standards-Native Interoperability

- **Status:** Accepted
- **Date:** 2026-09-16
- **Owner:** Architecture / Interoperability

## Context

Swasthya Core Labs must interoperate with arbitrary HMS/EHR/EMR systems. A
proprietary JSON envelope replacing HL7/FHIR semantics would create lock-in
and integration friction.

## Decision

- Use **established standards** as the interop lingua franca:
  - **HL7 v2** (primary messaging; target v2.5.1, verify per jurisdiction)
  - **FHIR R4** (primary REST API)
  - **DICOM/DICOMweb** at the imaging boundary (references only)
  - **IHE profiles** as profile-based navigation (verify statuses with the
    IHE registry)
  - **LOINC / SNOMED CT / UCUM** for terminology
- Adapters isolate protocol details from the clinical core (internal ports).
- No proprietary envelope replaces standard semantics.
- Cross-cutting: validation + quarantine, idempotency, replay protection,
  correlation identifiers, provenance, versioning, capability negotiation.

## Consequences

- **Positive:** integration-ready for standard-conformant external systems;
  no vendor coupling; leverages existing conformance tooling.
- **Negative:** standards conformance work (profiles, validation fixtures)
  is substantive; some external systems are non-conformant, requiring mapping
  and exception handling.
