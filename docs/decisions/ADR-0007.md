# ADR-0007: Identity, Tenancy, and Facility Isolation

- **Status:** Accepted (design deferred to Phase 1; Phase 1 basis recorded in ADR-0009, ADR-0010)
- **Date:** 2026-09-16
- **Owner:** Architecture / Security

## Context

Multi-site/enterprise deployments need isolation between organizations and
facilities; the platform must not depend on a particular external identity
provider, while supporting integration with national/enterprise identity.

## Decision

- **Facility-scoped data and authorization boundary**: every clinical data
  access is scoped to a facility/tenant context; cross-facility access is
  explicit and audited.
- **RBAC with ABAC-style attribute constraints** where needed; least
  privilege and deny-by-default.
- **Internal identity/access is CORE**; external identity providers are
  INTEGRATION (OAuth 2.0/OIDC integration boundary).
- Exact tenancy granularity (organization → facility hierarchy) and token/
  session design are **deferred to Phase 1** design.

## Consequences

- **Positive:** isolation is architected from the start, avoiding later
  rework; vendor-neutral identity.
- **Negative:** multi-tenancy complicates data model and access enforcement —
  deferred intentionally, not ignored.

  `docs/architecture/domain-boundaries.md`.
