# ADR-0014: Testing Foundation against Real PostgreSQL

- **Status:** Accepted
- **Date:** 2026-09-16
- **Owner:** Quality

## Context

Concurrency (`xmin`), DB-level audit protection, unique-partial indexes, and
facility scoping are only meaningful when proven against a real PostgreSQL.

## Decision

- **DB-backed tests run against real PostgreSQL**, tagged `Category=Db`, in:
  - `Swasthya.CoreLabs.Tests` — pure unit tests (no DB).
  - `Swasthya.CoreLabs.Persistence.Tests` — repositories, UoW context,
    constraints, xmin concurrency, audit immutability.
  - `Swasthya.CoreLabs.Api.Tests` — integration incl. facility isolation,
    cross-tenant denial, JWT validation, correlation/error/rate surfaces.
  - `Swasthya.CoreLabs.TestSupport` — shared seeding, JWTs, scratch-cluster
    factory, permission catalog.
- **Scratch cluster:** `scripts/pg-test.ps1` provisions a throwaway
  PostgreSQL on `127.0.0.1:55432` (state under `%TEMP%\scl-pg-test`,
  `SCL_PG_TEST_CONNECTION` or connection.txt). CI Ubuntu uses a
  `postgres:` service; the Windows job runs `Category!=Db`.
- Migrations are applied by `DbTestContextFactory.EnsureDatabase()`; API
  tests boot a `WebApplicationFactory` configured over the same database.

## Consequences

- **Positive:** high-confidence guarantees at the cost of a real server;
  deterministic isolation tests; CI parity for DB behavior.
- **Negative:** DB tests need a PostgreSQL instance; they are skipped where
  PostgreSQL is unavailable (documented filter).
- See ADR-0011, ADR-0012, ADR-0013, `docs/quality/quality-architecture.md`.
