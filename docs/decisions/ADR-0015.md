# ADR-0015: Laboratory Organization and Scope Model

- **Status:** Accepted
- **Date:** 2026-09-17
- **Owner:** Architecture

## Context

Phase 2 needs a laboratory organizational model to which master data is scoped:
organization → facility → laboratory section, plus a discipline axis. Phase 1
already models organizations and facilities (ADR-0007, ADR-0009, ADR-0010).
The alternative is to introduce a separate `Laboratory` aggregate as a new
tenancy or lifecycle root.

## Decision

- **Reuse Phase 1 `Organization` and `Facility`.** A "laboratory" is an
  organizational/facility configuration, not a new tenancy root; no separate
  `Laboratory` entity is introduced in this phase.
- Add two organizational axes:
  - `Discipline` — **organization-scoped**, extensible taxonomy entries
    (disciplines are data, never a hardcoded enum).
  - `LaboratorySection` — **facility-scoped** operational grouping.
- **Scope rules:** test identity, panels, units, code systems, result data
  types, result statuses, specimen types/sources, container types, disciplines,
  and analyzers are organization-scoped; laboratory sections, configuration
  items, analyzers, and reference ranges may also be facility-scoped.
  Organization-wide rows (`FacilityId is null`) are visible within their
  organization; facility-scoped rows are visible only within their facility.
- **Authorization:** organization-scoped master-data creation or change
  requires an **organization-wide grant** (`FacilityId is null`); facility-scoped
  changes require a grant at that facility or an organization-wide grant.
  A facility-only grant never authorizes another facility's data.

## Consequences

- **Positive:** no redundant tenancy root; consistent with Phase 1 isolation;
  disciplines and sections are configuration, not code.
- **Negative / trigger:** if a future phase requires multi-facility laboratory
  groupings or laboratory-level lifecycle ownership, introduce a `Laboratory`
  entity then and supersede this ADR.
- See ADR-0010 (facility-scoped RBAC), ADR-0016 (lifecycle/versioning).
