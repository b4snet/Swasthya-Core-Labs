# ADR-0017: Units, UCUM, and Terminology Mapping Boundary

- **Status:** Accepted
- **Date:** 2026-09-17
- **Owner:** Architecture / Clinical Informatics

## Context

Phase 2 needs unit and terminology structures without embedding proprietary or
authoritative content and without making interoperability or compliance claims
(ADR-0004, ADR-0008, `terminology-strategy.md`).

## Decision

- **`Unit`** stores an internal code, a name, and a UCUM expression string.
  UCUM syntax is validated **structurally only** (character class and length).
  The platform does **not** claim full UCUM validation, canonicalization,
  conversion, or round-trip fidelity in this phase.
- **`CodeSystem`** stores identifying metadata only (code, name, canonical URI,
  version-required flag). No terminology content is embedded.
- **`TestTerminologyMapping`** stores an explicit, versioned mapping row:
  test → code system → external code + external version + mapping status +
  effective window + provenance notes. **No external codes are invented or
  seeded**; mappings are configuration data supplied later from authoritative
  sources under license.
- Mapping lifecycle status (e.g. `Proposed`) is **structure only**; no
  terminology-server integration, validation, or re-coding runs in this phase.

## Consequences

- **Positive:** interoperability-ready data shapes without proprietary content
  or unsupported compliance claims.
- **Negative / deferred:** terminology service topology (embedded vs.
  external), licensing, mapping workflow, and canonical unit conversion remain
  future work.
- See ADR-0004, ADR-0008, `docs/interoperability/terminology-strategy.md`.
