# ADR-0020: Diagnostic Orders and Request Lifecycle Foundation (Phase 3)

## Context

The project adopted the Master Architectural Roadmap (0–55 numbering) per ADR-0019. Phase 3 implements the diagnostic orders and request lifecycle foundation for Swasthya Core Labs: order entities, order items with exactly-one-test-or-panel branching, CHECK constraint `ck_order_items_single_target`, new permissions `laboratory.order.read`/`laboratory.order.write`, idempotent order creation via `ExternalOrderId`, and Request→Cancelled lifecycle. No clinical workflows, patient data, specimen handling, results, or production integrations are included.

## Decision

- Implement the Domain/Application/Infrastructure/API layers for orders as specified in the Phase 3 design, including the CHECK constraint at the database level and domain enforcement preventing invalid state.
- Add permissions `laboratory.order.read` and `laboratory.order.write` using facility-scoped guards (`LaboratoryPermissionGuard.RequireFacilityScoped` + `LaboratoryScope.ResolveFacilityFilter`).
- Generate migration `AddDiagnosticOrderFoundation` adding `orders` and `order_items` tables with unique indexes, FKs Restrict, and the CHECK constraint.
- Provide API endpoints `POST /v1/organizations/{id}/orders`, `GET`, `PUT`, `POST /{id}/items`, `POST /{id}/items/{itemId}/transitions/cancel`, `POST /{id}/transitions/cancel`.
- Run the full test suite (≈+54 tests → 206 total vs 145 baseline) against a disposable scratch PostgreSQL cluster; all gates pass (`verify.ps1`).
- **Stop:** do not begin Phase 4, do not commit/push/deploy, do not expose to production or staging, do not handle real patient data.

## Consequences

- **Positive:** Phase 3 is verified locally against a real PostgreSQL cluster; all quality gates (format, Release build with warnings-as-errors, vulnerability scan, secret scan, git diff --check) pass; a 27-section Phase 3 Report is deliverable; the project can demonstrate a complete foundation for diagnostic orders without progressing to clinical workflows.
- **Negative / watch:** The project explicitly halts at Phase 3; any future phase (Phase 4+) requires its own execution specification and explicit authorization per the roadmap's phase execution and governance sections (ADR-0019). Existing references to "Phase 3" as PLANNED in ROADMAP.md §23 and the blueprint's CURRENT PROJECT POSITION must be updated to ACCEPTED / GREEN / FROZEN.
