## Context

Phase 8 (laboratory result **validation, verification, finalization and
controlled correction**) requires a complete, truthful inventory of the
result-derived entities and their requirement documents **before** design
and implementation. This ADR records that inventory and the requirement
gaps it exposes Nagios. It is a **documentation-only review**. It does not
modify production source, migrations, tests, APIs, permissions, audit, or
Result persistence.

## Requirement gaps (documented, not resolved)

### Gap 1 — Validation / Verification / Finalization / Correction semantics

The persistence-level semantics of validation, verification, finalization
and controlled correction are recorded as **4 UNRESOLVED decisions in
ADR-0022**. Phase 8 cannot begin implementation until ADR-0022 Decisions
1, 3, 4 resolve.

### Gap 2 — Clinical interpretation / validation rules evaluation

Clinical interpretation rules are out of scope and governed by clinical
governance. **No clinical rule, reference range, critical value, or CDS
invention.** This ADR documents that boundary only; it does not resolve
the evaluation model.

### Gap 3 — Uncontrolled mutation prevention

The repository already prohibits silent overwrite/delete of finalized or
unfrozen records via `Result.UpdateValue`/`ResultService` gating and
immutability (Phase 7). Phase 8 must not invent a substitute mechanism;
the existing gating carries forward. Representation of the *corrected
successor* is an ADR-0022 Decision 3 UNRESOLVED item.

### Gap 4 — Correction representation / history / provenance

Whether a correction creates a new successor identity (origin preserved,
successor references predecessor) or is a versioned amendment — and whether
the original finalized record must remain reconstructable — is
**UNRESOLVED** in ADR-0022 Decision 3. The repository requires history
reconstruction `original → correction → current effective` with no silent
overwrite and no deletion, per Phase 7 finalization invariants.

### Gap 5 — Result-validation ↔ CDS boundary

The boundary between result validation and clinical decision support /
interpretation is **not established** in the repo and requires **explicit
clinical governance** before Phase 8. This ADR does not cross it.

## Known gaps held as NOT-PHASE-8

- Clinical interpretation rules (clinical governance)
- Reference ranges, critical values (clinical governance)
- HL7 / FHIR / DICOM / analyzer integration (deferred phases)
- AI / CDS (deferred phases)

## Architectural decisions (this record)

Resolving the six mandated entity-architecture questions for the existing
`Result` entity only. Each entry is explicitly **DECIDED** or **UNRESOLVED
— REQUIRES EXPLICIT DECISION**. Smallest model that satisfies ADR-0022;
no new table, migration, field, or entity is created in this documentation
step.

### 1. Result identity — DECIDED

Corrected/finalized lifecycles reuse the existing `Result` identity; no
new identity is invented. ADR-0022 requires successor/amendment
representation **only if** a controlled correction occurs, and that
representation is itself an UNRESOLVED ADR-0022 decision — not an ADR-0023
creation.

### 2. Successor linkage — UNRESOLVED — REQUIRES EXPLICIT DECISION

How `original finalized Result → corrected successor` is represented
(successor identity vs. versioned amendment on the same identity vs.
both) is **not established**; it is ADR-0022 Decision 3, recorded
**UNRESOLVED — REQUIRES EXPLICIT DECISION** there appear.

### 3. Finalization metadata — UNRESOLVED — REQUIRES EXPLICIT DECISION

Whether verification/finalization metadata belongs directly on `Result`
(as fields), in a separate governed entity, or in another justified
structure is **not established** and requires the ADR-0022 lifecycle
resolution first. No convenience-only Result fields are added.

### 4. History — UNRESOLVED — REQUIRES EXPLICIT DECISION

The minimal mechanism that reconstructs `original → correction →
current effective` without deletion or silent overwrite is **not
established**; it follows the ADR-0022 correction-representation
resolution. No generic history framework is introduced without proof.

### 5. Validation — DECIDED (boundary)

Validation is **not** automatically a new Result status (ADR-0022,
Decision on structural reuse). Whether clinical/process validation is
transient-only, persisted separately, or represented otherwise is
**not resolved here** and remains an ADR-0022 UNRESOLVED item.

### 6. Concurrency — DECIDED

`Result.Version` (long) backed by PostgreSQL `xmin` optimistic
concurrency is reused unchanged. No new concurrency mechanism is added
for Phase 8 unless ADR-0022 explicitly requires one.

### 7. Audit separation — DECIDED

Administrative/security audit (ADR-0012, append-only) is **distinct** from
clinical result history/provenance. Audit is never a substitute for
clinical history.

## Phase 8 boundary — restated

- No implementation of the validation/verification/finalization/correction
  lifecycle.
- No migration, no new entity/field, no API, no permission, no test change.
- No clinical rule, reference range, critical value, or CDS behavior is
  invented.
- Original finalized results are never overwritten, deleted, or silently
  mutated.
